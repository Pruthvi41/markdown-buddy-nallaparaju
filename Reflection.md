## 1. How did AI assistance change your documentation workflow compared to writing it from scratch?

It mainly changed the *order* of the work, not the amount of it. Normally I'd write a README's section headers first and fill them in as I built the project. Here, I had Claude draft a full section outline before I'd written a single line of the R script, which was useful for knowing what to capture (I added inline comments to `sales_summary.R` specifically because the AI-suggested "Inputs/Outputs" structure made me realize I hadn't documented them yet). The actual writing was faster — a full README draft in one prompt instead of accumulating it over an hour — but every number and code example in the final file still had to come from me actually running the script, not from the draft. AI compressed the *drafting* step, not the *verification* step.

## 2. What are the risks of trusting AI-generated Markdown content without validation, and how did you mitigate them in this assignment?

The concrete risk showed up directly: Claude's first README draft included an "Example output" block with plausible-looking revenue numbers that were simply invented — it had no access to my actual dataset and filled the gap with something that read as correct. If I'd pasted that in unchecked, the README would have silently lied about what the project produces, which is worse than having no example at all because it looks authoritative. I mitigated this by treating every AI-drafted number as a placeholder until I'd run `scripts/sales_summary.R` myself and replaced the block with the real console output — and I kept the `.Rmd` file as a second, independent computation of the same numbers specifically so one could catch an error in the other (both matched: $696.87 total revenue, Coffee at $289.29). The syntax-level risk (broken code fences, wrong language tags) is lower-stakes but still real — I caught one `bash`-tagged block that was actually R and fixed it before committing.

## 3. Where did you need to make manual corrections to the AI's output, and why?

Three concrete corrections, each logged in the README's "AI Assistance Disclosure" section: (1) replacing the invented example numbers with the script's real output, described above; (2) trimming generic marketing-style language from the Overview section ("this powerful, flexible tool will transform your workflow") that didn't fit a one-script student project and that I wouldn't write myself; (3) fixing the mislabeled `bash` code-fence language tag on an R snippet, which would have broken syntax highlighting on GitHub. None of these were large rewrites, but all three were things I only caught by actually reading the draft line by line against the real project, not by skimming it — which is itself the main lesson from Rule 3 (manually verify all AI outputs; copying without validation is not allowed).
